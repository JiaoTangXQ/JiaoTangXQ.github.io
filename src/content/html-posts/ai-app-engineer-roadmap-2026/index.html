Roadmap / 2026

主线必修，支线选修

这条路线面向想从编程基础走到 [[LLM]]、[[RAG]]、[[Agent]]、评测和部署的人。主线是必学项，支线按岗位和项目需要选择。不要把 80 个节点当成打卡清单，要把每个阶段变成一个能运行、能被检查、能继续修改的作品。

约 1200 小时 每周 10 小时约 2 年多，每周 20 小时约 15 个月。
8 段主线 从 Python、API 和数据开始，走到 RAG、工具调用、Agent、评测和部署。
按作品验收 每段都有交付物。学会的证据是能做出来，并能解释失败原因。

适合谁

  • 想做 AI 应用开发，而不是只会和模型聊天的人。
  • 愿意补编程、数据、工程和部署基础的人。
  • 目标是做 RAG 问答、工作流 Agent、业务自动化、AI 产品原型或企业内部工具的人。

不适合谁

  • 只想学 prompt，提高日常办公效率的人。
  • 只想做算法研究、读论文、训练大模型的人。
  • 希望一两个月内掌握所有 AI 技术的人。

主线：AI 应用开发工程师必学项

主线的判断标准很直接：少了这一段，你就很难独立做出可上线的 AI 应用。CV、Diffusion、模型训练、并行加速和推理优化有价值，但它们不是每个 AI 应用开发者的第一条路。

1

编程与工程基础

180-220 小时

目标是能写脚本、调 API、处理文件、管理代码，并能定位常见错误。

  • Python
  • Git
  • VS Code
  • Jupyter
  • HTTP / JSON
  • 基础云服务
问 AI

“我会一点 Python。请用一个文件批处理任务检查我缺哪些基础，并给我 3 个递增练习。”

交付物

一个命令行小工具：读取 CSV，清洗数据，调用一个 API，输出结果文件，并写清楚运行方式。

2

数据与机器学习基础

180-220 小时

目标是理解数据怎样影响模型结果，能训练传统 ML 模型，并能判断评估结果是否可信。

  • Pandas / NumPy
  • 数据清洗
  • 特征工程
  • sklearn
  • XGBoost
  • 交叉验证
问 AI

“这是我的数据字段。请先判断任务类型、可能的数据泄漏、适合的指标，再给建模步骤。”

交付物

一个预测或分类项目：包含数据说明、训练脚本、指标解释、错误样本分析。

3

深度学习最小必需知识

120-160 小时

目标是读懂神经网络、Transformer、embedding 和训练过程的基本含义，能解释 LLM 应用为什么会出错。

  • 神经网络
  • PyTorch 基础
  • Transformer
  • embedding
  • token
  • 上下文窗口
问 AI

“请用一个客服知识库问答例子解释 token、embedding、attention 和上下文窗口分别影响什么。”

交付物

一份概念说明：能解释向量检索为什么会找错、上下文为什么会丢信息、模型为什么会编答案。

4

LLM API 与 Prompt 工程

160-220 小时

目标是把聊天模型接进真实程序，控制输入、输出、格式、成本和错误。

  • Messages
  • Structured Output
  • Streaming
  • Few-shot
  • 反问机制
  • 成本估算
问 AI

“请把这个模糊需求改写成一个 API 调用任务，列出输入字段、输出 JSON、失败情况和测试样例。”

交付物

一个文本处理服务：输入原始材料，输出结构化 JSON，并在格式错误时自动重试或报错。

5

RAG 与知识库问答

160-220 小时

目标是让模型基于指定资料回答，并能给出来源、拒答和错误记录。

  • 文档解析
  • 切片策略
  • 向量库
  • Hybrid Search
  • 引用来源
  • 召回评估
问 AI

“请帮我设计一个 RAG 测试集：20 个问题、期望答案、应引用的文档片段、找不到答案时的处理。”

交付物

一个文档问答系统：上传 5-20 篇资料，回答带来源，未知问题明确拒答，保留错误样本。

6

Tool Calling 与 Agent Workflow

140-200 小时

目标是让模型调用搜索、数据库、代码、文件和业务 API，并把多步任务拆成可观察的执行过程。

  • Function Calling
  • 工具权限
  • Agent Loop
  • 状态管理
  • 人工确认
  • 失败重试
问 AI

“这个任务有哪些步骤必须由程序执行，哪些步骤可以让模型判断，哪些动作需要人工确认？”

交付物

一个可追踪的 Agent：能查资料、调用工具、生成结果，并记录每次工具调用的输入、输出和失败原因。

7

评测、观测与安全边界

120-180 小时

目标是判断应用质量，而不是凭感觉说效果不错。每次改 prompt、模型、检索策略或工具权限，都要能回归测试。

  • Eval Dataset
  • 自动评分
  • 人工复核
  • Trace
  • 日志
  • Prompt Injection
问 AI

“请把这些历史失败案例改成回归测试，并给每条测试的评分规则和人工复核条件。”

交付物

一个评测面板或报告：至少 50 条测试样本，能比较不同版本的正确率、拒答率、延迟和成本。

8

部署、监控与产品化

140-200 小时

目标是把 demo 变成别人能使用的服务，并能处理权限、费用、延迟、限流和线上错误。

  • Docker
  • 云部署
  • 队列
  • 缓存
  • 限流
  • 成本监控
问 AI

“请把我的 AI 应用按线上服务检查：密钥、权限、日志、成本、错误处理、用户数据和回滚方案分别缺什么？”

交付物

一个可访问的 AI 应用：有登录或访问限制，有日志，有成本记录，有错误处理，有一份部署说明。

学习方式：每个节点都按作品推进

小白通常已经能找到资料，真正卡住的是下一句该问什么。每个节点都用同一个学习回路，AI 才能从聊天对象变成训练伙伴。

1. 定义任务 先说目标、人群、输入、输出、限制，不让 AI 直接开讲。
2. 让 AI 反问 要求它指出缺失信息、假设和风险。
3. 做最小练习 每次练习限制在 30-90 分钟，产出一个文件、接口、报告或测试集。
4. 用标准验收 要求 AI 按事先写好的标准批改，不接受泛泛评价。
5. 记录错误 把错因写成下一次 prompt、测试样例或检查清单。

通用提问模板

我的目标是：做出 X。
我的基础是：Y。
我现在卡在：Z。
请你先判断我缺的是概念、方法、代码能力还是练习量。
然后给我：
1. 一个最小学习步骤
2. 一个 60 分钟内能完成的练习
3. 交付物格式
4. 验收标准
5. 常见错误和检查方式

30 天起步计划

如果从零开始，不要第一天就研究 Agent 框架。前 30 天只做一件事：让自己能写代码、调 API、交付一个可运行小工具。

第 1 周

Python 基础、文件读写、JSON、命令行。交付一个文件整理脚本。

第 2 周

HTTP、API 调用、错误处理。交付一个调用 LLM API 的文本处理脚本。

第 3 周

Prompt 结构、输出格式、重试。交付一个把原始文本转成结构化 JSON 的工具。

第 4 周

小型 Web 接口、日志、测试样例。交付一个可本地访问的 AI 小服务。

阶段验收标准

学完一个阶段时，用下面 5 条检查。过不了，就不要急着进入下一个阶段。

  1. 能用自己的话解释这个阶段解决什么问题。
  2. 能做出一个可运行作品，而不是只保存教程代码。
  3. 能列出 3 个常见失败原因。
  4. 能让 AI 生成测试样例，并能判断测试样例是否覆盖主要情况。
  5. 能把错误记录改成下一版的约束、代码或评测用例。

参考资料

这份路线图的应用侧判断，主要参考了 2026 年 AI 应用开发里已经形成共识的几个方向：工具调用、Agent 运行过程、评测、可观测性和动手项目。

  • OpenAI Agents SDK 文档：把 agent 应用拆成模型、工具、状态、编排、人工确认和观测。
  • OpenAI Agent Evals 文档：用 traces、graders、datasets 和 eval runs 改进 agent 质量。
  • Hugging Face AI Agents Course：用工具、动作、观察、框架、作业和评测组织 agent 学习。
