> 这是这个站重启之后的第一篇文章。如果你来自旧版的宇宙画布，欢迎回来。
> 这里现在更朴素，但承载的内容更重。

## 为什么折叠掉宇宙画布

旧版焦糖星球是一个 GPU 渲染的"思想宇宙"：文章以发光行星的形态散布在无限画布上，按主题语义聚成星系。技术上是一份还算认真的作品 —— 五层渲染管线、四个自定义 GLSL shader、d3-force 布局、自动巡游相机。视觉上我自己挺喜欢。

但它有一个根本问题：**它是一个展示载体，里面没有内容。**

我以为漂亮的壳能等到内容慢慢长出来。事实是，壳越漂亮，写字的门槛越高 —— 因为我每写一篇都在想"这能配得上这个壳吗"，于是干脆不写。半年下来，画布里的几颗行星全是早年的旧文，外加一个为了"假装有更新"而做的外部 RSS 聚合管线。一个内容站靠转载支撑，是最尴尬的状态。

更现实的一击是流量。一个全 SPA 渲染的站，搜索引擎拿到的 HTML 只有 1.5KB，里面除了一个空 div 什么也没有。sitemap 只收录了首页一条 URL。Google 不可能把这种站排上来。我当时觉得"内容好了流量自然会来"，但内容根本就没有。

## 一个不那么舒服的对照

最近我注意到 [yage.ai](https://yage.ai)（grapeot 的 Computing Life）。从外观看朴素得几乎让人觉得平庸 —— 一个倒序时间排列的文章列表，没有任何动画，没有任何视觉花活。但它的访问量很大，文章频繁被技术圈讨论。

我花了一个下午做对比，结论很简单也很难听：

- 他写得**多**：原创长文几十篇，AI、Agentic 工程、系统设计、摄影、航空，深度足够。
- 他写得**清**：每篇文章都把一个具体问题讲到底，不堆砌、不快讯。
- 他**容易被读到**：每篇都是独立的静态 HTML，URL 语义化，title/正文/标签直接进 HTML，搜索引擎一进来就拿到全部信号。
- 他有**身份**：grapeot 这个名字在技术圈是认得出来的，X 上发文章自带流量。

他做对的三件事，我一件都没做。

## 把这件事看清楚之后做的决定

我把整个旧版站打包归档成 git tag `v0.1-cosmos-archive`，然后从零开始重写。新栈是 Astro 5 + MDX + 极少量 React island，没有再做任何花活。设计上是单栏 editorial 杂志风：宋体正文、克制的强调色、留白、把文字本身放在 C 位。

具体做了什么：

1. **删干净。** 整个外部 RSS 聚合管线（160 个源、四套过滤清洗脚本、几千篇缓存）一次性删除。这一步最难下手，但它必须走 —— 转载内容既无法带来 SEO，也无法建立"为什么读你"的理由。
2. **静态化。** 每篇文章都是预渲染的 HTML，正文、标题、描述、Open Graph 都直接进 source。Google、ChatGPT、Perplexity 任何爬虫进来都能直接读到全部内容。
3. **保留宇宙画布作为彩蛋。** 旧的 GLSL 代码迁到 `/universe` 路由作为一个 React island，在主导航里不暴露，只在页脚一个隐蔽链接。它不会再阻塞流量，但也没有被丢掉。
4. **承诺写作。** 这是这一切真正的前提。如果接下来的 60 天我没写出 8 到 10 篇值得发的原创长文，前面三步都会归零。

## 这个站接下来会怎么写

一条规则：**要么把一件事讲透，要么不写。**

具体倾向：

- 工程话题为主：AI Agent、系统设计、前端、性能。
- 偶尔写阅读笔记和方法论，但不写"日记式"快讯，不写"今天在看什么"。
- 不追热点，不写情绪向短文。
- 一篇文章一个问题，结束时让读者多带走一点东西。

频率不承诺。我宁愿一个月只发一篇能拿出手的，也不发四篇凑数的。
