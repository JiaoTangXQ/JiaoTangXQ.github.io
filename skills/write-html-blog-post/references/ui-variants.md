# UI Variants

Pick one variant per post. Choose based on article shape; do not rotate randomly.

## minimal-essay

Use for reflective essays, arguments, and ordinary text-heavy posts.

Pattern: title, deck paragraph, single reading column, pull quote optional.

## notebook

Use for exploratory notes, unfinished thinking, learning logs, and idea fragments.

Pattern: dated note feel, short sections, side notes or callouts, visible tags.

## case-study

Use for projects, debugging stories, experiments, and before/after writeups.

Pattern: context, constraint, attempt, result, lesson. Include screenshots or code only when they change understanding.

## field-report

Use for observations from tools, workflows, events, products, or communities.

Pattern: what happened, what I noticed, why it matters to me, what I will try next.

## reading-note

Use for book/article/course notes.

Pattern: source, strongest idea, disagreement, extracted concepts, follow-up links.

## timeline

Use when sequence matters: build logs, launch notes, migration logs, travel-like records with privacy-safe locations.

Pattern: chronological entries with short timestamps or dates. Avoid precise private location or routine data.

## gallery-note

Use for image-heavy posts, visual references, design explorations, and screenshots.

Pattern: image grid or stacked figures with captions. Redact screenshots before use.

## code-lab

Use for technical walkthroughs and implementation notes.

Pattern: problem, minimal reproduction, code blocks, result, tradeoffs. Remove secrets, local paths, private repo names, and internal hostnames.

## index-map

Use for posts that introduce a cluster of concepts or link several old posts.

Pattern: short intro, concept list, relationship notes, many internal links and `[[concept]]` nodes.
